# 個人旅行足跡與動態行程記錄 App 設計規格書 (Travel Footprint & Trip Journal App)

**日期：** 2026-10-19  
**狀態：** 草案 (Draft)

---

## 1. 意圖與核心動機 (Intent & The Why)

使用者希望擁有一個**專屬於個人的私密旅行紀錄空間**，同時滿足兩種核心渴望：
1. **遊戲化的探索成就感（點亮世界）**：每當踩點一個地標、城市或國家，就能在世界地圖上「解鎖並點亮」該區域，直觀看見自己的人生探索進度（已訪國家數、城市數、地標數）。
2. **溫暖且有質感的回憶留存（拍立得故事卡 + 獨立旅程日誌）**：不只是冷冰冰的座標圖釘，每個踩點都是一張包含照片、當下天氣、同行旅伴與隨筆短評的「拍立得回憶卡」；同時，每一次出發旅行都能建立獨立的「旅程本（Trip）」，在旅途中即時更新每日行程與打卡紀錄，並自動匯流至頂層的人生總足跡庫。

此外，這套系統的「總足跡庫」與「獨立旅程本」採取**雙層解耦且可擴充的架構**，確保未來能輕鬆掛載新功能（如 3D 迷霧、花費模組、心願清單、路線軌跡等），而不必重構核心資料模型。

## 2. 目標、非目標與反目標 (Goals, Non-Goals, Anti-Goals)

### 目標 (Goals)
1. **雙層分離且自動連動的體驗**：
   - **層級一：總體足跡庫 (Lifetime Footprints)**：匯聚所有已訪地標與點亮區域（國家/行政區），提供全球與區域統計面板，並支援依年份、國家、同行旅伴篩選。
   - **層級二：獨立旅程本 (Trips & Live Journal)**：以「單趟旅行」為單位（如「2024 京都賞楓 5 日遊」），支援按天數（Day 1, Day 2...）管理行程節點。旅途中可隨時新增/更新打卡紀錄，打卡後自動同步點亮「總體足跡庫」。
2. **拍立得風格的踩點故事卡 (Landmark Polaroid Card)**：
   - 每個地標打卡記錄包含：主圖照片（支援多張，首張作為拍立得封面）、隨筆短評與個人星級評分（1~5 星）、造訪日期時間、自動抓取（或歷史查詢）的天氣與溫度資訊（如 `☀️ 22°C`）、以及同行旅伴標籤（Companions）。
3. **過去旅行回憶的雙軌補登 (Retroactive Entry)**：
   - **智慧照片批次匯入**：選取舊照片後，自動解析 EXIF 中的 GPS 經緯度與拍攝日期時間，自動反查地標/城市/國家與歷史天氣，快速在地圖上生成打卡草稿供確認。
   - **手動地圖搜尋與插旗**：針對無照片或無 EXIF GPS 的回憶，提供地名搜尋（Geocoding）與地圖直接點擊插旗，手動指定造訪日期、旅伴與心得。
4. **跨裝置無縫體驗 (Mobile + Desktop)**：
   - 旅途中在手機瀏覽器（或安裝為 PWA）能單手快速打卡、傳照片、更新當日行程。
   - 回到家在電腦大螢幕上能舒適瀏覽世界點亮地圖、整理批次舊照與回味旅程時間軸。
5. **高擴充性資料架構 (Extensibility)**：
   - 足跡點（Footprint Entry）與旅程節點（Trip Stop）均預留結構化擴充欄位（`metadata` JSON 欄位與模組化關聯），未來新增「花費記帳」、「交通票根」、「心願清單（To-Go）」或「成就徽章」時無須破壞既有資料。

### 非目標 (Non-Goals — 現階段不做)
- **不做公開社群與多人協作**：無須註冊帳號體系、好友追蹤、公開貼文牆或留言點讚。完全服務單一使用者個人使用。
- **不做複雜財務記帳**：不內建多幣別匯率換算、分帳計算機或細項收支報表。
- **不做複雜遊戲徽章系統**：聚焦於「點亮地圖區域 + 數量統計」，暫不設計繁瑣的特殊條件徽章規則。

### 反目標 (Anti-Goals — 即使技術可行也絕不應該發生的事)
- **不得讓打卡流程變得像填寫繁瑣表單**：旅途中站在地標前打卡必須在 15~30 秒內完成（選照片/定位 → 寫一句話 → 儲存），絕不能因為必填欄位過多而破壞旅行當下的興致。
- **不得將「總足跡」與「單次旅程」死綁在一起**：使用者可以單純補登一個「過去某年去過的地標」而不必強制建立一整個多日旅程（Trip）；反之，在旅程（Trip）中新增的已訪地標必須自動出現在總足跡庫，不能要求使用者重複輸入兩次。
- **不得綁死在封閉專有格式**：所有旅行足跡、照片與行程資料必須支援完整匯出（JSON / GeoJSON + 照片打包），確保個人珍貴回憶永遠屬於使用者自己。

## 3. 限制與執行條件 (Constraints)

- **執行環境**：Windows 開發環境，目標產出為可同時在手機與電腦瀏覽器流暢運行的現代 Web 應用程式（支援 PWA 安裝與響應式佈局）。
- **零付費 API 門檻（Zero-Cost / Self-Contained External APIs）**：
  - 地圖底圖與圖磚：使用開源免 API Key 的向量/柵格圖磚（MapLibre GL JS / Leaflet 搭配 OpenStreetMap / CartoDB 圖磚，以及 Natural Earth 國家/行政區 GeoJSON 邊界資料以實現「點亮區域」效果）。
  - 地名搜尋與逆地理編碼（Reverse Geocoding）：使用免金鑰的 Nominatim (OpenStreetMap) API，並加上適當快取與節流。
  - 天氣自動補完：使用免金鑰的 Open-Meteo API（同時支援即時天氣 `Forecast API` 與歷史天氣 `Historical Weather API`，能根據打卡的經緯度與歷史日期自動查出當天的天氣代碼與溫度！）。

## 4. 已確認的設計決策 (Decided How)

### 4.1 雙層核心領域模型 (Dual-Layer Domain Model)

系統由兩個核心領域模型組成，透過關聯 ID 鬆散耦合：

1. **足跡點 (`Footprint` / `PlaceVisit`) — 屬於「總體足跡庫」**
   - 代表使用者在某個時間點對某個地標的實際造訪紀錄。
   - 核心屬性：
     - `id`: UUID
     - `title`: 地標/地點名稱（如「清水寺」、「台北 101」）
     - `coordinates`: `{ lat, lng }`
     - `countryCode` / `countryName`: ISO 國家代碼與名稱（用於點亮世界地圖國家區域）
     - `regionName` / `cityName`: 城市或一級行政區名稱（用於統計與區域點亮）
     - `visitedAt`: 造訪日期與時間（支援精確日期時間，或僅回憶起年月）
     - `photos`: 照片陣列（含縮圖、原圖儲存路徑與拍攝 EXIF 資訊）
     - `note`: 隨筆短評
     - `rating`: 1~5 星評分（選填）
     - `weather`: `{ conditionCode, conditionText, tempC, icon }`（由 Open-Meteo 自動帶入，可手動微調）
     - `companions`: 旅伴 ID 陣列（關聯至 `Companion` 旅伴標籤表，如「家人」、「小美」、「獨旅」）
     - `tripId` & `tripDayId`: （選填）若此踩點源自某趟旅程，指向該旅程與天數；若為單獨補登則為 `null`
     - `extensions`: `{}`（預留擴充結構，供未來掛載票根、花費、徽章等模組）

2. **旅程本 (`Trip` & `TripDay` & `TripItem`) — 屬於「獨立旅程與動態日誌」**
   - 代表一次完整的旅行專案（例如「2025 北海道冬日行」）。
   - 核心屬性：
     - `Trip`: `id`, `title`, `coverPhoto`, `startDate`, `endDate`, `status` (`planning` | `active` | `completed`), `companions` (預設同行旅伴，新增該趟打卡時自動繼承), `summaryNote`, `extensions`
     - `TripDay`: `id`, `tripId`, `dayNumber` (Day 1, Day 2...), `date`, `title` (如「抵達京都・東山散步」)
     - `TripItem`: 每日行程中的一個節點。
       - 可為「預定行程點（Planned Stop）」或「已打卡踩點（Visited Stop，直接關聯一筆 `Footprint`）」。
       - 旅途中，使用者點擊預定行程點的「打卡踩點」按鈕，或直接在當前 `TripDay` 點擊「＋新增即時踩點」，即可上傳照片與心情，系統同時完成 `TripItem` 更新與 `Footprint` 總庫寫入。
       - 地圖視角切換至單一 `Trip` 時，會用路線軌跡線將該趟旅程依序造訪的地標串連起來。

### 4.2 視覺與互動體驗 (UI/UX Architecture)

- **頂部/側邊雙主軸導覽**：
  1. **🌍 世界足跡 (World Map & Achievements)**：
     - 頂部懸浮成就膠囊：`已解鎖 N 個國家 · M 個城市 · K 個地標`（點擊可展開探索統計面板）。
     - 互動式世界地圖：已造訪的國家/區域呈現溫暖點亮色塊（未造訪區域呈現柔和暗色/迷霧感），地圖上分布「拍立得縮圖圖釘（Photo Pins）」。
     - 篩選器列：可依「全部 / 年份 / 國家 / 同行旅伴」即時過濾地圖上的圖釘與下方卡片流。
     - 點擊任一圖釘：彈出高質感**拍立得故事卡（Polaroid Modal）**，展示相片、手寫感短評、日期、天氣溫度圖示與旅伴標籤。
  2. **🎒 我的旅程 (Trips & Live Journal)**：
     - 顯示所有旅程卡片列表（進行中置頂、過往旅程依年份排列）。
     - 點入單一旅程：左側（手機版為可切換抽屜/分頁）為 **Day 1 / Day 2 行程時間軸**，右側（或上半部）為**該趟旅程專屬路線地圖**。
     - 旅途中支援一鍵「＋新增踩點紀錄」與拖曳調整當日行程順序。
  3. **✨ 快速新增 / 舊照補登 (Quick Check-in & Retro Import)**：
     - **即時打卡**：讀取目前 GPS 或拍照上傳，自動帶入當下座標、地名、即時天氣與當前進行中旅程（若有）。
     - **批次照片補登精靈**：拖入或選取多張舊照片 → 前端解析 EXIF GPS 與拍攝時間 → 自動分組並呼叫 Open-Meteo 歷史天氣與 Nominatim 逆地理編碼 → 產生預覽拍立得清單 → 使用者可批次設定「所屬旅程」與「同行旅伴」後一鍵匯入。
     - **手動搜尋補登**：輸入地標名稱搜尋座標（或點擊地圖任意處插旗），選擇歷史日期，系統同樣自動補齊該日歷史天氣。

## 5. 技術選型（Builder 預設決策 — 可由使用者覆蓋）

由於使用者將技術棧全權交由我們決定，以下為針對「手機與電腦雙端瀏覽、本機私密儲存且易於擴充」所選擇的預設方案（Marked as Builder's Call）：

- **前端框架**：**React 18 + TypeScript + Vite + Tailwind CSS**
  - 理由：元件化程度高，支援 PWA（Progressive Web App），手機與桌面響應式設計極為成熟。
- **地圖引擎**：**MapLibre GL JS (搭配 React-Map-GL 或原生封裝)** + **Natural Earth 國家邊界 GeoJSON**
  - 理由：無須綁定信用卡或付費 Token，支援平滑的 2D/3D 地球儀與區域填色（點亮國家色塊）、自訂拍立得照片 DOM 圖釘，以及旅程路線繪製（GeoJSON LineString）。
- **資料儲存與跨裝置策略**：**輕量化本機後端 (Node.js + Express/Fastify + SQLite 資料庫 + 本機圖片資料夾儲存)**
  - 理由：因為定位為「個人私密使用」，採用 SQLite 單一檔案資料庫搭配本機原圖/縮圖儲存：
    1. 沒有瀏覽器 IndexedDB 容量上限或清理快取導致照片遺失的風險。
    2. 在電腦啟動服務後，同一區網（或透過 Tailscale / 隧道）的手機可直接打開網址打卡並將照片存回電腦硬碟；同時內建「一鍵 JSON + 照片匯出/匯入備份」功能。
- **照片 EXIF 解析**：`exifr`（高速讀取 JPEG/HEIC/PNG 中的 GPS 座標與 `DateTimeOriginal`）。
- **外部公開 API 整合**：
  - **OpenStreetMap Nominatim API**：地標關鍵字搜尋與經緯度轉國家/城市名稱。
  - **Open-Meteo Archive & Forecast API**：免 API Key，傳入 `(lat, lng, date)` 自動取得當日天氣狀況（WMO Weather Code）與平均/最高氣溫。

以下細節在規劃與實作階段由工程師自行決定最佳實踐：
- 具體的色彩配置表（建議採用溫暖復古奶油白/深邃星空藍主題，凸顯拍立得相紙與點亮色塊的質感）。
